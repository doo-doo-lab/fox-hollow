# 小狐大世界 - 项目策划文档

> 最后更新：2026-09-10

## 一、项目概述

- **项目名称**：小狐大世界（Fox Hollow Tales）
- **类型**：增量放置 / 村庄建设
- **灵感来源**：Kittens Game（猫国建设者），玩法机制相似，但所有文案、命名、主题完全原创
- **主题**：玩家经营一个狐狸山谷村落，从采集野莓开始，逐步建造设施、吸引村民、发展科技
- **风格**：白底黑字纯文字界面，紧凑单行排版
- **线上地址**：https://akira17189-create.github.io/fox-hollow/（GitHub Pages，推送后自动更新；旧地址 https://2d9lpj7e.mule.page/）

| 灵术 | 消耗 | 效果 | 限制 |
|------|------|------|------|

### 2.7 季节系统

每年4个季节循环，每季 100 天（游戏内时间）。1 天 = 10 tick = 2 秒；一季 3 分 20 秒，一年 13 分 20 秒。

| 季节 | 野莓产量倍率 | 特殊效果 |
|------|-------------|----------|
| 早春 | ×1.5 | 丰收季 |
| 盛夏 | ×1.0 | 正常 |
| 金秋 | ×1.2 | 略丰 |
| 寒冬 | ×0.25（庇护后×0.4） | 产量骤降，需提前囤粮 |

### 2.8 满意度系统

- 基础值：100%
- 人口 > 5 时，每多1只狐狸 -2%
- 灵狐祠每座 +5%
- 研究「狐灵传说」+10%
- 范围：10% ~ 200%
- 影响手动采集野莓的产量
- 影响全体职业产出（乘以满意度百分比）
- 悬浮面板显示计算明细及当前职业产出倍率

### 2.9 人口系统

- 狐狸通过「狐狸窝」提供容量（每座+2）
- 当容量有余且野莓 > 20 时，有 1.5% 概率每 tick 迁入新狐狸
- 研究「先祖之眼」后狐狸消耗野莓 -15%（0.35→0.30/s）
- 野莓耗尽时，每 50 tick 有一只狐狸离开
- 每只狐狸消耗野莓 0.35/s

### 2.10 事件系统

#### 山谷见闻
- 26 种随机事件，约每 11 分钟触发一次（概率 0.0003/tick）
- 四大类：灵启（需灵狐祠）、天象、山谷异象、过客与声音
- 加权随机选取，部分有季节/建筑前置条件
- 部分事件附带资源奖励

#### 世界的回响
- 18 段极稀有叙事文本，约每 3 小时触发一次（概率 0.00002/tick）
- 按季节分类（春4/夏5/秋5/冬4），仅当前季节可触发
- 斜体蓝灰色显示，与普通日志区分
- 纯叙事，无资源效果

#### 遗光获得日志
- 被动发现、手动采集触发、山谷见闻、丰收祭奖励、在线/离线远行奖励统一经过 `logRewards()`，使用暗金色斜体（`remnant`，`#9a7b4f`，与资源面板遗光一致）。
- 普通发现与固定奖励文末附「（遗光 +1）」；含多项资源时遗光放在清单末尾。远行有斥候/研究倍率时显示实际 `+N`，不改变奖励数量。
- 日志生成只格式化已经结算的奖励，不再加资源；普通叙事及不含遗光的奖励保持原有颜色。

### 2.11 存档系统

- **自动存档**：localStorage，每 30 秒自动保存
- **手动存档**：Header「存档」按钮
- **存档码**：Base64 编码导出/导入，支持跨设备迁移
- **后台补算**：页面仍存活时，按真实经过时间推进；长间隔调用 `simulateOffline()`（含季节更替、狐狸消耗、饥荒、迁入、远行、商队）。单次最大补算时间 24 小时。
- **后台节流补偿**：浏览器对后台页签降频时，主循环累积欠账并补跑 tick；游戏内部切页签不能控制引擎是否推进。
- **现有限制**：当前存档没有持久化现实时间戳，完全关闭页面后再打开不会自动补算关闭期间的时间；跨会话离线补算列入 Backlog，不把现有后台补算误写为已完成该功能。

## 三、UI 设计

- **风格**：白底黑字，纯文本，无图标无装饰
- **布局**：三栏（左：资源 | 中：操作 | 右：日志）
- **建筑行**：单行紧凑「名称 (数量) 费用 [建造] [出售]」
- **费用不足**：红色高亮
- **Tab**：营火 / 村落 / 工坊 / 研究 / 山外（研究解锁）

### 3.1 悬浮信息面板

所有游戏元素名称支持鼠标悬停显示信息面板（`position: fixed`，JS 定位防溢出）：
- 建筑：描述 + 效果数值 + 解锁提示 + 短句
- 职业：描述 + 每人产出 + 短句
- 研究：描述 + 加成百分比 + 短句
- 工坊：描述 + 短句
- 资源：短句 + 特殊提示
- 满意度：显示计算明细

### 3.2 短句系统

- 数据中以 `tip` 数组存储，支持多句
- 每季缓存一次，季节更替时刷新
- 风格：冷幽默、有哲思、克制、口语化
- 旧墟仅保留「有的门还开着，像在等谁回来吃饭。」；云岭仅保留「从那上面看，村子小得像一个念头。」。两地 `tip` 数组均只有一项。

### 3.3 面板折叠（v0.12.3）

- 资源栏：点击「资源」标题折叠/展开，包含狐狸村民行和全部资源。
- 中栏：点击当前页签折叠/展开；点击其他页签切换，并保留该页签自己的折叠偏好。营火、村落、工坊、研究和解锁后的山外均支持。
- 日志栏：点击「谷中见闻」标题折叠/展开；隐藏期间仍记录日志，展开显示最新内容。
- 所有折叠控件使用原生按钮，支持触屏、Enter、空格；显示「收起 / 展开」，同步 `aria-expanded`、`aria-controls`；页签还标记 `aria-pressed`。周期刷新不重建页签按钮，避免焦点丢失。
- `fhFold = {res, log, tab:{b,v,c,r,w}}` 保存本机偏好，默认展开；只接收已知键和布尔值，坏 JSON、异常字段或存储受限不会阻断游戏。刷新恢复偏好，存档导入不覆盖偏好。
- 手机（≤860px）：资源 → 操作 → 见闻自然单列排列，取消 160px 内部滚动区；折叠使用 `hidden` 真正消除占高，后续内容立即上移。折叠按钮/页签至少 44px 高，窄屏控件自动换行。
- 电脑（>860px）：资源 200px、日志 230px、中栏弹性伸展；折叠只隐藏内部内容，不移动或重排列。三列 x 坐标与宽度保持不变。
- 折叠不暂停生产、远行、自动制作、自动存档；无论内容可见与否，均由同一个引擎计时。

### 3.4 公共远行进度（v0.12.2）

- `center-body` 内的公共远行区域位于当前页签操作内容之前；营火、村落、工坊、研究、山外都能看到同一组队伍的最新进度。
- `rExpeditions()` 仅从 `G.expeditions` 渲染，复用进度条节点；派遣仍在山外进行，不创建额外倒计时或重复结算。
- 当前页签折叠时，连同公共进度区域一起隐藏，避免手机残留占高；游戏照常推进，展开即显示最新进度。

## 四、技术实现与项目架构

### 4.1 工作区布局与 Git 边界

```text
/workspace/                        # /app 指向此工作区
├── .git/                          # 仓库历史、分支、远端配置；仅留在根目录
├── reference/                     # 第三方参考资料；仅本地，不提交
├── uploads/                       # 原始上传文件；不提交
└── output/                        # 可交付项目，也是 Git 工作树
    ├── .gitignore
    ├── README.md
    ├── index.html                 # 页面入口；相对路径加载 css/js
    ├── css/
    │   └── style.css              # 三栏布局、移动端、悬浮信息、日志与进度条
    ├── js/
    │   ├── data.js                # 静态规则与叙事数据
    │   ├── engine.js              # 游戏状态、计时、结算、存档
    │   └── ui.js                  # 展示、交互、折叠、启动入口
    ├── tests/                     # 仅开发时使用，不参与游戏加载
    │   ├── helpers.cjs            # Node VM / 可控时钟夹具
    │   ├── engine.test.cjs        # 引擎与数据回归（零依赖）
    │   ├── logs.test.cjs          # 遗光来源、旧日志队列与奖励数量回归
    │   ├── browser_test.py        # 隔离 Chromium 界面回归
    │   ├── capture_ui.py          # 一次性测试村落截图与布局测量
    │   ├── requirements.txt       # 仅测试用 Playwright
    │   └── README.md              # 测试方法
    └── docs/
        ├── RULES.md               # 协作规则
        ├── design.md              # 本文档
        ├── changelog.md           # 按版本记录事实变更
        ├── panel-collapse-plan.md # 本次折叠实施方案、风险检查和验收清单
        └── validation.md          # 本次验证结果、测量与范围限制
```

本地 `.git/config` 仅增设 `core.worktree = ../output`，其余远端和身份配置保留。这样 Git 元数据仍在工作区根目录，项目文件全部放在 `output/`；从工作区根目录或 `output/` 执行 Git 均操作同一个工作树。

**远端仓库路径从工作树开始**：`output/index.html` 提交为 `index.html`，而不是 `output/index.html`。不迁移 GitHub Pages 入口，不改变线上 URL 和 localStorage 所属 origin。`reference/`、`uploads/` 位于工作树之外，`.gitignore` 另保留 `reference/` 防误放。不要将 `.git/config` 或任何凭据放进交付文件。

### 4.2 模块职责

| 模块 | 负责 | 边界 |
|------|------|------|
| `data.js` | `RD/BD/JD/UD/CD/SD`、季节/时间常量、`EXD/CVD/NARR/CHOICE_EVENTS` | 只放规则和文案，不依赖 DOM |
| `engine.js` | `G`、资源/人口计算、`tick/tickOnce/simulateOffline`、远行/贸易/抉择、存档迁移 | 游戏推进不以当前页签或面板可见性为条件 |
| `ui.js` | `rAll/rRes/rTabs/rTC/rExpeditions/rLog/rSeason`、悬浮信息、页签与折叠、`startGame` | 读取状态并展示；交互调用引擎操作，不在渲染中扣时间或结算奖励 |
| `style.css` | 桌面三列、≤860px 单列、各类日志与控件状态 | 折叠不改变桌面列宽，不使用占高的隐藏方式 |
| `index.html` | 固定页面容器与脚本加载顺序 | 依次加载 data → engine → ui；无需框架、打包或运行时依赖 |

当前使用普通 `<script>` 共享全局作用域；引擎的交互操作仍会调用 UI 刷新/日志函数，后续模块化需显式处理这些接口，不把现状描述成完全无耦合。

### 4.3 状态与数据流

```text
静态数据 data.js → initState / migrate → 游戏状态 G
真实时间 → tick → tickOnce / simulateOffline → 资源、人口、远行结算
玩家按钮 → 引擎操作 → G → rAll / rLog → DOM
fhSave ↔ G；存档码 ↔ G；fhFold ↔ 界面折叠偏好（独立）
```

- 200ms 为一个 tick；`TPD=10`，`DPS=100`；界面通常累计推进 5 tick（约 1 秒）后刷新。
- `tickDebt` 保存不足 200ms 的毫秒余数；正常/节流回调和长补算共用时钟，跨长间隔不丢 tick。超过 5 秒的整 tick 批次走静默补算；恢复前台通过 `visibilitychange` 立即同步，重复同一时刻回调不重复推进。
- `resetClock()` 在读取/导入存档时清理运行时欠账；时钟回拨不会产生负欠账。这些字段不写入游戏存档。
- 引擎资源速率单位是每游戏日量：每 tick 加 `s.r / TPD`，显示每秒值为 `s.r × 0.5`。
- `G` 持久化游戏进度；当前页签、短句缓存、日志列表和现实时间计时器为运行时状态。
- `fhFold` 是本机界面偏好，折叠不改变 `fhSave`，不影响旧存档导入。
- `G.pendingNarr` 保存 `{m, c}` 日志条目，保留离线奖励的类别；`normalizePendingNarr()` 兼容旧字符串队列并过滤非法项。日志用 `textContent` 渲染，存档里的文本不会当作 HTML 执行。
- GitHub Pages 发布现有仓库根目录静态文件，线上地址见第一章；Mule Pages 为历史发布地址。

### 8.7 远行系统

#### 操作流程

1. 在「山外」Tab 选择目的地
2. 消耗资源（野莓干粮 + 铜钱路费 + 符咒灵力）
3. 派出 1-3 只闲置狐狸（锁定为外出状态）
4. 等待游戏内天数倒计时
5. 返回：获得资源奖励 + 随机返回日志；旧墟/云岭另附带一段叙事碎片

#### 远行记录结构

`G.expeditions` 数组，每条记录：

```
{
  dest: string,          // 目的地 ID（nearHill / forest / oldRuin / cloudRidge）
  foxCount: number,      // 派出狐狸数
  ticksLeft: number,     // 剩余 tick 数
  totalTicks: number,    // 总 tick 数（用于进度条计算）
  usedSpiritPath: boolean // 是否已对此次远行施放过灵路
}
```

#### 目的地

| 目的地 | 路程 | 消耗 | 解锁条件 |
|--------|------|------|----------|
| 旧墟 | 30天 | 野莓50, 铜钱2 | 驿道×1 |
| 云岭 | 60天 | 野莓100, 铜钱5, 符咒1 | 驿道×1, 瞭望塔×1, 研究：远途跋涉 |
| 荒丘 | 100天 | 野莓200, 铜钱8, 符咒4 | 驿道×3, 瞭望塔×1 |
| 密林 | 150天 | 野莓300, 铜钱10, 符咒8 | 驿道×3, 灵狐祠×2 |

路程受瞭望塔缩减：每座 ×0.85（2 座 = ×0.72，3 座 = ×0.61）。

#### 奖励池

每次返回从目的地奖励池抽取 2-3 项，数量 = 基础数量 × (1 + 斥候数 × 0.2) × (研究「远途跋涉」? 1.5 : 1)。

| 目的地 | 奖励池（基础数量） |
|--------|-------------------|
| 旧墟 | 矿铁 3-6, 古币 1-2, 遗光 1（10%概率），叙事碎片（必定） |
| 云岭 | 符咒 3-5, 古币 2-3, 叙事碎片（必定） |
| 荒丘 | 碎石 10-20, 兽皮 1-3, 香料 1（40%概率） |
| 密林 | 圆木 15-25, 兽皮 2-4, 丝帛 1（40%概率） |

旧墟和云岭每次必定返回一段叙事碎片（按顺序推进，不重复抽取）。

#### 抉择事件

斥候 ≥ 2 时，远行返回有概率触发抉择事件。玩家从 2 个选项中选择，不同选项导致不同后果（资源变化、新事件加入事件池、特殊状态等）。无最优解。

已实装 5 个抉择事件（刻名墙/南迁之问/石标修缮/掌印墙/旧墟老狐狸），每个含 2 个选项与不同后果。

#### 叙事碎片收集状态

已收集的叙事碎片以 `G.narratives` 持久化：

```
G.narratives = {
  oldRuin: [],      // 已解锁的旧墟碎片索引数组，如 [0, 1, 2]
  cloudRidge: []    // 已解锁的云岭碎片索引数组
}
```

远行返回时，取 `G.narratives[dest].length` 作为下一条碎片的索引，若未超出数据总条数则推入。山外 Tab"叙事碎片"区域按序展示已收集条目，未收集的显示为"???"占位。

#### 外出狐狸状态

- 新增 `G.foxAway` 追踪外出狐狸数
- 派出时：`G.foxAway += n`，`G.freeFox -= n`
- 返回时：`G.foxAway -= n`，`G.freeFox += n`
- 外出狐狸**不消耗村内野莓**（出发时已扣干粮）
- 外出狐狸**不受饥荒减员影响**
- 野莓消耗计算用 `G.foxes - G.foxAway`
- `rmFox()` 只从村内狐狸（含职业和闲置）中移除

### 8.8 商队系统

外来商队为其他物种的狐族或山谷中的灵兽，周期性到访。

#### 机制

- 商队冷却计数达到 2 后，每次季节更替有 50% 概率到访；当前实现没有「最多 3 季必来」保底，到访后停留至本季结束
- 到访时日志提示，「山外」Tab 显示商队商品

- 冷却追踪：`G.caravanTimer`（整数），商队离开时重置为 0；同次季节更替又进入无商队分支并 +1。无商队时每季 +1，达到 2 后进行概率判定；在场时不额外计数

#### 商队类型

| 白鹤信使 | 卷轴×2 = 铜钱12 | 符咒×2 = 铜钱10 | 砖块3 → 铜钱5 | 灵狐祠×1 |
