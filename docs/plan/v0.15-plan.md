## 一、资源循环体系总览

改动后形成三环嵌套结构：

```
内环（基础循环）：野莓/圆木/碎石/兽皮 → 加工品 → 建筑/研究
中环（贸易循环）：香料/丝帛 ↔ 染丝/果酒/墨锭 → 节令消耗 + 灵术消耗 + 建筑维持
外环（灵性循环）：符咒 → 灵术 → 临时增益 → 推动内环/中环效率
```

核心设计原则（参考猫国）：
- 每种资源至少有 2 个消耗场景
- 稀有资源有 3 条以上获取路径
- 建筑有维持消耗，不是"建了就完事"
- 转化品消耗后产生增益，增益反过来加速基础生产（正反馈环）

## 二、香料获取扩展（5 条路径）

### 2.1 猎手「林间采风」（新机制）

每季结算时做一次概率判定：

```
发现概率 = min(0.5, 0.12 × 在岗猎手数 + 0.03 × 猎手授业等级)
成功 → 获得 1 香料（需 spice 上限 > 0 且未满）
```

| 猎手数 | 授业 0 | 授业 2 | 授业 4 |
|--------|--------|--------|--------|
| 1 | 12% | 18% | 24% |
| 2 | 24% | 30% | 36% |
| 3 | 36% | 42% | 48% |
| 4+ | 上限 50% | 50% | 50% |

- 解锁条件：猎手 ≥ 1 + 驿道 ≥ 1（即 spice.mx > 0）
- 期望产量：3 猎手 + 授业 1 级 ≈ 1.6 香料/年
- 主题：猎手在山林活动，发现野生香草
- **数值对照**：12% 基础 + 3% × 授业的设计参考职业授业系统"每级 +10% 产出"——授业 4 级把 12% 推到 24%，恰好让一只猎手在 4 级满授业时单季触发概率翻倍。50% 上限避免后期"猎手必出香料"破坏稀缺感。年产 1.6 香料约等于山猫行商一次访问购买量（2 香料），定位为"被动稳产"

日志池：

```js
const HUNTER_SPICE_LOGS = [
  '猎手在溪谷背阴处发现了一丛野香草，小心翼翼地连根拔起。',
  '追猎物的路上踩到了什么，低头一看是长满了的香料苗。',
  '一只猎手说山坡上有股味道不对劲——是好的那种不对劲。',
];
```

### 2.2 商贩「路边生意」（新机制，含进度条可视化）

引擎追踪计数器 `G.merchantSpiceAcc`，**该计数器对玩家可见**（避免猫国贸易系统对照下"不透明"的体验问题）：

```
每 tick：G.merchantSpiceAcc += 在岗商贩数 × 实际铜钱产率（含授业/满意度/加成）
当 G.merchantSpiceAcc ≥ 15 时：
  G.merchantSpiceAcc -= 15
  35% 概率获得 1 香料（需 spice 上限 > 0 且未满）
  失败时也输出日志，让玩家知道系统在运作
```

- 解锁条件：商贩 ≥ 1 + 商驿 ≥ 1
- 期望产量：3 商贩（授业 1 级）≈ 0.6 香料/年
- 主题：商贩在做买卖过程中顺带从路过旅客手里换到香料
- **数值对照**：商贩基础铜钱 0.005/s（[design.md:71](docs/design.md:71)），3 商贩 ≈ 0.015/s。阈值 15 = 1000s ≈ 50 游戏天 ≈ 半季触发一次。35% 概率让平均年产 ≈ 0.6 香料，约为猎手路径（1.6/年）的三分之一——商贩定位为"小额辅助"而非主力

UI 呈现：商贩职业 hover 面板新增进度条 `[████████░░] 12.3 / 15`，玩家可看到接近触发的紧张感。

日志池：

```js

  '一个路过的旅狐用一小包香料抵了欠款，商贩欣然收下。',
  '集市角落换到了一撮来路不明的香料——闻着是正宗的。',
  '商贩说今天做了笔好买卖，顺手掏出一包带味儿的东西。',
];

const MERCHANT_SPICE_FAIL_LOGS = [

  '本来要换香料的旅客临时改了主意。',

```

### 2.3 商队到访赠礼（新机制）

任何商队到访时 40% 概率附赠 1 香料（需 spice.mx > 0）。

```js
// trySpawnCaravan() 生成商队成功后
if (G.res.spice.mx > 0 && Math.random() < 0.4) {
  G.caravan.gift = { r: 'spice', a: 1 };
}
```

日志附加："……顺手留下一小撮路上采的香草。"

- 期望产量：约 2 次商队/年 × 0.4 = 0.8 香料/年
- **数值对照**：商队冷却 ≥ 2 季（[design.md:467](docs/design.md:467)）→ 年均 ≈ 2 次。40% 概率比"图纸携带 50%"略低，定位为"赠品而非常规携带"——玩家对赠品有期待感但不依赖。0.8 香料/年与商贩路径同档

### 2.4 旧墟远行掉落（数据改动）

`EXD.oldRuin.rewards` 新增：

```js
{ r: 'spice', min: 1, max: 1, prob: .25 }
```

主题依据：旧墟叙事碎片 #2 提到"铁针、针孔里留着炭化的线"——废墟中有手工业遗迹，残存香料合理。

- 期望产量：约 0.5 香料/年（取决于远行频率）
- **数值对照**：旧墟现有奖励"遗光 10% 概率"是稀有档、"矿铁/古币必给"是常态档。25% 介于两者之间，让香料"不是必给但有期待"。1-1 单位避免远行成为香料主产，鼓励玩家组合多条路径

### 2.5 山猫行商购买（现有，不变）

2 香料 / 8 铜钱，每次商队驻留可购买 1 次。

### 2.6 枯风口远行掉落（条件性，见 §16.5）

## 三、丝帛获取扩展（3 条路径，纳入 autoCraft）

> **重要声明**：本章新增的两个工坊配方（纺丝帛、换丝帛）**与现有染丝/果酒/墨锭/木板/砖块/卷轴配方同等对待**，解锁 craftMastery 后可设置自动制作，无需额外研究。

### 3.1 纺丝帛配方（新工坊配方）

```js
weave: {
  n: '纺丝帛', d: '兽皮+圆木 → 丝帛',
  inp: [{ r: 'leather', a: 5 }, { r: 'wood', a: 5 }],
  out: [{ r: 'silk', a: 1 }],
  uq: { b: { artistry: 1 } },
  tip: ['不是正经蚕丝，但搓出来一样滑溜。']
}
```

- 解锁条件：艺工坊 ×1（后期本地自给）
- 不构成循环依赖：解锁艺工坊之前通过河獭商队/互兑获取丝帛→做染丝→解锁百艺通觉→建艺工坊→解锁纺丝帛
- 成本说明：5 兽皮 + 5 圆木 → 1 丝帛。设定为"商队不来 + 香料紧缺（无法走互兑路线）"时的本地替代方案，定位为兜底而非首选。河獭商队 5 铜钱/丝帛仍更划算。
- **数值对照**：河獭商队 10 铜钱 = 2 丝帛 = 5 铜钱/丝帛，是市场基准。3 商贩年产铜钱 ≈ 43，购买力 ≈ 8.6 丝帛/年；纺丝帛若全力跑（猎手 0.06 兽皮/s = 26 兽皮/年 ÷ 5）≈ 5.2 丝帛/年——本地配方产能比商队购买低，符合"兜底"定位。原 8 兽皮 + 5 圆木 改为 5+5 是把"永远劣于商队"调整为"略劣但可用"

### 3.2 香料互兑配方（新工坊配方）

```js
spiceToSilk: {
  n: '换丝帛', d: '香料+铜钱 → 丝帛',
  inp: [{ r: 'spice', a: 3 }, { r: 'coin', a: 5 }],
  out: [{ r: 'silk', a: 1 }],
  uq: { b: { tradePost: 1 } },
  tip: ['三袋香料加五枚钱，过路的河獭掏出一匹丝，双方满意。']
}
```

- 解锁条件：商驿 ×1（中期可用）
- 有损兑换：3 香料 + 5 铜钱 → 1 丝帛，防止套利
- 让铜钱参与循环，给铜钱增加消耗场景
- **数值对照**：山猫 8 铜钱 = 2 香料（4 铜钱/香料），河獭 10 铜钱 = 2 丝帛（5 铜钱/丝帛）。本地互兑 3 香料 + 5 铜钱 = 17 铜钱等价（按山猫单价折算）→ 比河獭直购的 5 铜钱贵 3.4 倍，明确定位为"商队不来时的应急"，避免套利

### 3.3 河獭商队购买（现有，不变）

2 丝帛 / 10 铜钱。

### 3.4 远途跋涉研究费用下调

## 四、节令系统（新机制——手动触发版）

### 4.1 机制（修订：手动 vs 自动的取舍）

研究「百艺通觉」完成后自动启用。

**关键设计决策**：节令为**每季手动触发**，而非自动消耗。

- 自动版会与盈库灵术抢资源（玩家想存染丝施放盈库时，季节切换被节令吃掉）
- 自动版玩家体验是"我的东西莫名其妙少了"，违反路线图"持续做小决策"原则
- 手动版每季一次主动决策，与节庆施放频率一致

UI：每季开始时风俗 Tab 顶部弹出节令面板：

```
┌─ 本季节令 ─────────────────────────────┐
│  ☐ 染丝 ×1 → 全职业产出 +5%            │
│  ☐ 果酒 ×1 → 野莓产量 +8%              │
│  ☐ 墨锭 ×1 → 学识产出 +10%             │
│  三全礼：三者均选 → 满意度 +5% + 全产出 +3% │
│                            [确认] [跳过]│
└──────────────────────────────────────────┘
```

- 选"跳过"= 不消耗不加成（保存资源给灵术用）
- 选部分 = 只消耗选中的，按部分加成生效
- **默认勾选沿用上一季选择**（避免挂机玩家每季都需手动；首次出现时默认全勾）

**节令模式设置（拍板 A1）**：

设置面板（顶部 Header → 设置 → 节令）提供二选一：

| 模式 | 行为 | 适用人群 |
|------|------|---------|
| **静默自动**（默认） | 季节切换时按上季默认静默 auto-apply，不弹面板；玩家想改打开常驻 banner 中的"展开调整"折叠面板 | 偏好挂机不被打扰的玩家 |
| **必须手动确认** | 季节切换时弹出面板挡住游戏，玩家必须点击确认/跳过才能继续；不点击则节令该季完全跳过（既不消耗也不加成） | 偏好"每季亲自决策"的玩家 |

存档字段：`G.riteMode = 'auto' | 'manual'`，默认 `'auto'`。migrate 补默认。

### 4.2 数据定义

```js
const SEASON_RITES = {
  dye:  { consume: 1, desc: '穿新衣干活有精神' },   // 全职业产出 +5%
  wine: { consume: 1, desc: '微醺的狐狸摘得更多' }, // 野莓产量 +8%
  ink:  { consume: 1, desc: '研墨读书效率高' },     // 学识产出 +10%
};
// 三全礼 = 三者全选 → +5% 满意度 + 3% 全产出（allM 加法）
```

### 4.3 引擎实现

季节切换时不再自动扣除，而是写入 `G.pendingSeasonRites`：

```js
// 季节切换时
G.pendingSeasonRites = {
  open: true,
  defaults: G.lastSeasonRites || { dye: true, wine: true, ink: true },
};
```

玩家点击确认（或 1 季内未操作自动按 defaults 应用）时：

```js
function applySeasonRites(selection) {
  G.seasonRites = {};
  for (const [res, cfg] of Object.entries(SEASON_RITES)) {
    if (selection[res] && G.res[res].v >= cfg.consume) {
      G.res[res].v -= cfg.consume;
      G.seasonRites[res] = true;
    }
  }
  G.seasonRites.all = G.seasonRites.dye && G.seasonRites.wine && G.seasonRites.ink;
  G.lastSeasonRites = selection;        // 记忆下季默认
  G.pendingSeasonRites = { open: false };
}
```

`calcR()` 中应用：

```js
if (G.seasonRites.dye)  jobMul += 0.05;
if (G.seasonRites.wine) berryMul += 0.08;
if (G.seasonRites.ink)  loreMul += 0.10;
if (G.seasonRites.all)  allMul += 0.03;  // 三全礼全产出 +3%
// calcH() 中
if (G.seasonRites.all) h += 0.05;       // 三全礼满意度 +5%
```

### 4.4 数值对照

**单档加成（染丝 +5% / 果酒 +8% / 墨锭 +10%）**：

- 对照祖灵灵术（[design.md:106](docs/design.md:106)）：全职业 +50%、消耗 8 符咒、每季限一次
- 节令染丝 +5% 全职业 = 祖灵的 1/10 强度，但消耗"1 染丝（=1 香料 + 1 丝帛 = 2 个稀有资源）"也比 8 符咒（学者 + 灵狐祠产出可挂机攒）更稀缺。换算下来强度/成本比相近，定位为"轻量持续增益"
- 果酒 +8% 略高于染丝是因为只作用于野莓单维度（vs 染丝的全职业），范围窄换数值高
- 墨锭 +10% 学识独占——学识在前期是研究瓶颈、后期价值递减，所以给最高的单项数值平衡阶段感

**三全礼（修订：+3% → +5%+3%）**：

原设计三全礼仅 +3% 满意度，对照单座月光井永久 +3% 满意度（[design.md:52](docs/design.md:52)，造价仅 20 碎石+2 矿铁），每季都要投入的回报反而与一座永久建筑相同——严重不划算。

修订为：**+5% 满意度 + 3% 全产出（allM 加法）**。

- +5% 满意度：对照灵狐祠 +5%/座（[design.md:51](docs/design.md:51)）。三全礼一次性投入持平一座灵狐祠的永久效果——但只持续 1 季——保持"瞬时强但需持续投入"的张力
- +3% 全产出：对照月光井 +3%/座、商驿 +2%/座。三全礼属于"叠加在所有建筑外的额外增益层"，让玩家有动力维持三全而不是只选单项

### 4.5 正反馈环

果酒加成野莓 +8% → 更多野莓 → 更多果酒原料 → 维持加成。
参考猫国"猫薄荷→精炼木→更多田→更多猫薄荷"的自我强化循环。

### 4.6 挂机与离线行为（详细设计）

> idle 游戏的核心体验是"离开几小时回来发现进展"。手动节令必须解决一个矛盾：**主动决策密度** vs **挂机不被打扰**。原 R1 只写了"未操作自动跳过"——玩家挂机 = 节令大概率不施放 = 功能闲置。R2 改用"默认沿用上季 + 多重兜底"。

#### 4.6.1 五种玩家场景的行为矩阵（按 `G.riteMode` 分支）

**判定"玩家在场"**（A4 拍板）：使用浏览器 `document.hidden` API——`document.hidden === false` 即玩家正在看游戏 tab。其他情况（最小化/切到别的 tab/电脑息屏）一律视为不在场，按挂机处理。

| 场景 | riteMode | 上季选择 | 资源 | 行为 |
|------|----------|---------|------|------|
| **首次解锁**（百艺通觉刚完成） | 任意 | 无记录 | 够 | 弹出**全屏引导面板**（一次性，riteIntroSeen 控制）→ 引导后才弹常规面板，默认全勾 |
| **首次解锁** | 任意 | 无记录 | 不够 | 同上，但不够的项 disabled + 提示缺口 |
| **挂机切季**（不在场） | auto | 染丝+果酒 | 够 | 季节切换时按上季默认静默自动应用，不弹面板，加进 offlineRiteLog |
| **挂机切季** | auto | 染丝+果酒 | 染丝够 / 果酒不够 | 部分应用（只扣染丝），缺的项加 offlineRiteLog 标记 |
| **挂机切季** | manual | 任意 | 任意 | 不消耗不加成，本季节令完全跳过；玩家回来通过 banner 可手动选下季 |
| **在场切季** | auto | 任意 | 任意 | 静默自动应用 + 顶部 toast 提示"本季节令已应用：染丝+果酒（+5%/+8%）"，玩家可点 toast 上的"撤销"按钮（限 60 秒内） |
| **在场切季** | manual | 任意 | 任意 | 弹出**模态面板**挡住主操作区，必须点击 [确认] 或 [跳过]——不点击则一直停在切季前状态等待玩家操作 |
| **玩家中途切换 riteMode** | — | — | — | 当季已应用的不撤销；下一季按新模式生效 |

#### 4.6.2 跨季离线（玩家挂机 ≥ 1 季）

挂机 8 小时 ≈ 1 游戏年 ≈ 4 次季节切换 ≈ 4 次节令触发。

**`simulateOffline()` 中的处理**：

```js
// 离线期间每个季节切换时
function offlineSeasonRiteApply() {
  const defaults = G.lastSeasonRites || { dye: true, wine: true, ink: true };
  applySeasonRites(defaults);  // 按上季模板自动结算（资源不够的项自动跳过）
  G.offlineRiteLog.push({
    season: G.season,
    applied: { ...G.seasonRites },  // 记录哪些项实际生效
    consumed: { ... },
  });
}
```

**回到游戏时的总结 toast**（一次性显示，避免日志刷屏）：

```
┌─ 离开期间（约 8 小时 / 4 季）────────────────────┐
│  节令均按上次设置应用：染丝 + 果酒                  │
│    · 染丝消耗 4，果酒消耗 4                       │
│    · 第 3 季果酒不足，仅染丝档生效                  │
│    · 累计加成贡献：野莓 +8% × 3 季 + 全职业 +5% × 4 │

```

#### 4.6.3 资源保护开关（玩家显式控制）

玩家可在节令面板设置"低于阈值时跳过"——避免资源被吃光：

```
┌─ 本季节令 ─────────────────────────────┐
│  ☑ 染丝 ×1 → 全职业产出 +5%            │
│     ⚙ 染丝 < [3] 时跳过（保留给灵术）  │
│  ☑ 果酒 ×1 → 野莓产量 +8%              │
│     ⚙ 果酒 < [3] 时跳过                │
│  ☐ 墨锭 ×1 → 学识产出 +10%             │
│                            [确认] [跳过]│
└──────────────────────────────────────────┘
```

- 阈值默认 0（即"资源够就用"）
- 玩家想攒资源给灵术时可设置阈值 ≥ 4（保留至少 2 次盈库灵术的量）
- 阈值在玩家修改后持久化（`G.riteThreshold = { dye: 3, wine: 3, ink: 0 }`）
- 离线补算时尊重阈值——不会把染丝吃到不够施放盈库

#### 4.6.4 首次解锁的特殊处理

百艺通觉研究完成的下一个季节切换：

- 弹出**全屏引导面板**（非普通季节面板）解释机制：
  ```
  ╔═══ 节令系统 ═══════════════════════════╗
  ║  村中有了百艺通觉的根基，每季可借文化   ║
  ║  品换得加成。                          ║
  ║                                        ║
  ║  · 染丝、果酒、墨锭三选其一或多         ║
  ║  · 三全礼可叠加额外加成                ║
  ║  · 资源够才生效，不够自动跳过           ║
  ║  · 上季选择会作为下季默认               ║
  ║                  [明白了，本季选择 →]  ║
  ╚════════════════════════════════════════╝
  ```
- 之后才弹常规节令选择面板，默认全选

引导面板只显示一次（`G.riteIntroSeen = true` 持久化）。

#### 4.6.5 UI 持续可见的状态指示

玩家不打开节令面板时，仍需知道当前季节令状态：

- **风俗 Tab 顶部小 banner**（折叠态）：

- **季节切换 toast**：每季切换时短暂显示一行 "【春】节令已应用：染丝+果酒"

#### 4.6.6 状态字段汇总（`G` 新增）

```js

G.riteIntroSeen = false;                                   // 首次引导已看
```

migrate() 全部置默认值（见第九章）。

#### 4.6.7 设计权衡说明

| 选项 | 优点 | 缺点 | 取舍 |
|------|------|------|------|
| 自动扣除（R1 原设计） | 0 操作 | 抢资源 / 违反持续决策 | ✗ 弃用 |
| 纯手动每季弹（极简版） | 决策清晰 | 挂机回来一年节令全跳过 | ✗ 弃用 |
| **沿用上季 + 双模式（auto 默认 / manual 可选）**（A1 拍板） | 默认对挂机友好 / 想严格的玩家有 opt-in / 决策可触达 | 字段多 / UI 复杂度略高 | ✓ 采用 |

核心判断：**节令的"决策性"主要体现在"上次决策的复用 + 玩家想改时能改"**，而非"每季强制重选"。这与猫国的政策切换、施放仪式的频率体感一致——但部分玩家偏好严格手动节奏（"我要每季亲自做决定"），所以提供模式开关让玩家自选。

## 五、文化灵术（3 个全新效果维度）

### 设计原则

不与现有灵术效果重叠。现有灵术已覆盖：野莓产量(祈雨)、全职业产出(祖灵)、建筑造价(丰收祭)、远行时间(灵路)、商队召唤(商风)、满意度(山谷宴席)。新灵术覆盖三个空白维度：资源上限、工坊产出、研究费用。

### 5.1「盈库」（修订：+30% 上限 + 满仓溢出保护）

```js
overflow: {
  n: '盈库', d: '本季资源上限 +30%；满仓时溢出部分以 50% 效率继续累积至临时上限',
  cost: [{ r: 'dye', a: 2 }],
  uq: { u: { artistryLore: 1 } },
  tip: ['本来放不下了——但换个方式叠，居然又挤进去了。']
}
```

- 消耗：染丝 ×2
- **设计修订**：原 +40% 纯加上限会让玩家陷入"猜时机"焦虑——施放过早收益不足，施放过晚溢出已浪费。修订后 +30% 上限并加入"满仓溢出半效继续累积"，玩家可季初施放然后安心挂机。
- 每季限一次
- 与储藏窖/石窖（永久上限）不重叠：盈库是临时的且有溢出保护
- **数值对照**：储藏窖/石窖永久上限提升约 30-50%，盈库 +30% 临时档贴近这条线下限。50% 溢出效率参考猫国寒冬野莓 25%（不归零）的"半效兜底"设计原则。染丝 ×2 消耗对应的成本 ≈ 4 个稀有资源（2 香料 + 2 丝帛），约 1 季的累积——施放成本与效果时长（1 季）匹配

### 5.2「双工」（修订：×2 → +50%）

```js
doubleCraft: {
  n: '双工', d: '本季所有工坊制作产出 +50%（加法叠加在 craftMul 上）',
  cost: [{ r: 'wine', a: 2 }],
  uq: { u: { artistryLore: 1 } },
  tip: ['一锤下去多崩出半个，狐狸自己都吓了一跳。']
}
```

- 消耗：果酒 ×2
- **设计修订**：原 ×2 翻倍会制造"囤积爆发"退化策略——理性玩家永远不在非双工季节制作，攒够原料一次性爆发。这与 idle 游戏稳态产出理念冲突。
- 修订为 +50% 加法叠加（在 craftMul 上），收益降低但仍强力（持平祖灵 +50%）。囤积 3 季原料的机会成本不再划算，玩家在非双工季也会正常制作。
- 每季限一次
- 无重叠：祖灵加职业产出，不影响工坊配方；丰收祭减建筑造价，不影响工坊
- **数值对照**：祖灵 +50% 全职业 8 符咒（[design.md:106](docs/design.md:106)）。双工 +50% 工坊单季持平祖灵职业档，但作用域窄（仅工坊 vs 全职业），果酒 ×2（=60 野莓的工艺成本）比 8 符咒便宜——价值平衡靠"作用域窄"换"成本低"

### 5.3「墨契」（修订：限 1 季有效期）

```js
inkPact: {
  n: '墨契', d: '下一次研究花费 -40%；本季内无效则消失',
  cost: [{ r: 'ink', a: 2 }],
  uq: { u: { artistryLore: 1 } },
  tip: ['写一份契约跟学识讲价，居然成了。']
}
```

- 消耗：墨锭 ×2
- 效果：`G.inkPact = G.season`（标记当前季度），下次成功研究时若仍在同季，费用 ×0.6（乘法叠加学者「划重点」天赋），用掉后归 -1
- 同时设 `G.inkPactBp = true`（提升下一支商队图纸携带概率 +15%，见 §12.3）
- **季末检查**（A3 拍板）：季节切换时若 `G.inkPact !== G.season - 1` 则**同时清零** `G.inkPact = -1` 和 `G.inkPactBp = false`——研究折扣和图纸概率加成必须一起作废，否则下季玩家不施墨契也能撞到 +15% 商队图纸
- **设计修订**：原无限期版"无脑存最贵研究用"，没有真正抉择。修订为 1 季有效期后玩家需判断"这个季节内能否攒够最贵研究的资源"——攒不够不如用在中等价位，否则白费 2 墨锭。
- 不限每季施放次数，但施放后直到用掉/季末前不可再施放
- 无重叠：丰收祭减建筑造价；学者划重点是永久 -10%；墨契是一次性 -40%
- **数值对照**：丰收祭 -30% 建筑造价 3 符咒；学者「划重点」-10% 永久。墨契 -40% 是一次性研究档，强度比丰收祭高（建筑频次比研究高，研究单次决定权重大），覆盖一次贵研究的边际收益约等于跳过半次同等研究——值得用 2 墨锭换

> 关于墨契与图纸概率的额外效果：见第十二章 §12.3。墨契生效期间会同时提升下一支商队的图纸携带概率（一次性 +15%）。

### 灵术汇总（修订后）

| 灵术 | 消耗 | 效果 | 空白维度 | 限制 |
|------|------|------|----------|------|
| 盈库 | 染丝×2 | 本季上限 +30% + 满仓溢出半效累积 | 资源上限 | 每季一次 |
| 双工 | 果酒×2 | 本季工坊产出 +50%（加法） | 工坊产出 | 每季一次 |
| 墨契 | 墨锭×2 | 下次研究 -40%（限本季）+ 下支商队图纸概率 +15% | 研究费用 / 图纸概率 | 用掉/季末前不可重复 |

三个灵术分别消耗三种不同文化资源，每个数值都对照现有灵术（祈雨 5 符咒、祖灵 8 符咒、丰收祭 3 符咒）调过，强度合理。

## 六、建筑维持消耗（修订：半效模式）

参考猫国熔炉/反应堆"建筑需要养"模式，为文化建筑引入维持成本。

**关键设计修订**：原"断供归零"是断崖惩罚——挂机回来发现符咒归零了几季什么都没攒到，体验极差。修订为**半效运作**，保留惩罚感但不至于挂机回来一无所有。参考猫国寒冬野莓 25%（不归零）。

### 6.1 月歌台

- 维持：1 果酒/年（每年第一个季节自动扣除）
- 正常效果：符咒 +0.003/s
- **断供效果：符咒产出 ×0.25（保留 25% 基础产出）**
- 主题：月夜歌咏需要酒，酒尽歌淡
- **数值对照**：1 果酒/年的维持档对照瞭望塔 1.0 符咒/季持续消耗（[design.md:355](docs/design.md:355)）。果酒比符咒稀缺（需 30 野莓 + 工艺时间），所以频率降为 1/年（瞭望塔是 4/年）。25% 半效参考猫国寒冬野莓 25%——保留兜底产出但有明显惩罚感（玩家会想办法补货）

### 6.2 艺工坊

- 维持：1 染丝/季
- 正常效果：`craftCultureMul +0.05` × 座数
- **断供效果：`craftCultureMul ×0.5`（文化配方加成减半，不归零）**
- 主题：作坊需要持续染料供应
- **数值对照**：染丝是双稀有资源合成品（1 香料 + 1 丝帛），每季 1 染丝维持比月歌台更频繁（4× 频率）但不沉重。50% 半效（vs 月歌台 25%）是因为 craftCultureMul 本来就是小数加成（每座 +5%），减半比归零体验更合理——避免"5 座艺工坊忽然加成全消失"的断崖

### 6.3 实现方式

季节切换时检查并扣除，标记失效状态：

```js
// 月歌台：每年春季扣果酒
if (G.season === 0 && G.bld.moonStage.c > 0) {
  if (G.res.wine.v >= G.bld.moonStage.c) {
    G.res.wine.v -= G.bld.moonStage.c;
    G.moonStageActive = true;
  } else {
    G.moonStageActive = false;
  }
}

// 艺工坊：每季扣染丝
if (G.bld.artistry.c > 0) {
  if (G.res.dye.v >= G.bld.artistry.c) {
    G.res.dye.v -= G.bld.artistry.c;
    G.artistryActive = true;
  } else {
    G.artistryActive = false;
  }
}
```

`calcR()` 中：

```js
// 月歌台符咒产出（断供半效）
const moonMul = G.moonStageActive ? 1 : 0.25;
r.charm += BD.moonStage.e.charmP * G.bld.moonStage.c * 5 * moonMul;

// 艺工坊加成（断供半效）
const artMul = G.artistryActive ? 1 : 0.5;
const craftCultureMul = BD.artistry.e.craftCultureMul * G.bld.artistry.c * artMul;
```

### 6.4 维持消耗显示在资源速率面板（新增）

`resBreakdown()` 中追加维持消耗显示，让玩家在果酒/染丝 hover 时直接看到维持负担——避免"季节切换才发现莫名其妙少了"：

```js
}
```

## 七、文化建筑线改为双分支

### 7.1 改动前（单链）

```
树荫堂 → 月令新酿 → 月歌台 → 岁时有常 → 百艺通觉 → 艺工坊
```

## 八、锻造炉循环依赖修复

### 问题

锻造炉产出矿铁 0.008/s（实际值，非 design.md 表中过时的 0.004/s），铁器冶炼研究需要 10 矿铁。无铁匠时需等约 21 分钟纯空转。

### 修复：首炉赠铁 + 研究降费

**8.1 首次建造赠铁**

锻造炉从 0→1 时赠送 3 矿铁（恰好够建灵狐祠造价）：

```js
// build() 中
if (id === 'smithy' && G.bld.smithy.c === 1) {
  G.res.iron.v = Math.min(G.res.iron.v + 3, G.res.iron.mx);
  log('锻造炉第一炉出铁了，获得 3 矿铁。');
}
```

- 3 铁可立即用于建造灵狐祠（需 3 铁），获得即时正反馈
- 主题："第一炉出铁"是冶金里程碑
- **数值对照**：灵狐祠造价含 3 矿铁（[design.md:51](docs/design.md:51)）——首炉赠 3 铁恰好让玩家"建炉立即可建灵狐祠"，不留空转期。这是"建筑赠送量 = 下一座需要的量"的精准对齐设计

**8.2 铁器冶炼研究降费**

```js
// 原：p: [{ r: 'lore', a: 40 }, { r: 'iron', a: 10 }]
// 改：
p: [{ r: 'lore', a: 40 }, { r: 'iron', a: 5 }]
```

改后流程：建炉送 3 铁 → 再攒 2 铁（约 1-2 分钟）→ 完成研究。空转期从 21 分钟缩短到 1-2 分钟。

## 十二、商队来访概率与图纸出现概率加成

### 12.1 现状分析

当前游戏中没有任何机制可以提升：
- 商队来访概率（固定每季 50% 判定，冷却 ≥2 季后才能再来）
- 商队携带图纸概率（固定 50%，商贩「野路子」激活时 60%）

这两项是中后期玩家最渴望提升的"元概率"，因为它们直接影响游戏节奏。

> **重要修订（R2）**：原 R1 设计在远行返回时按 baseBpProb=0.20 抽图纸——但**远行系统当前从不返回图纸**，图纸只来自商队携带。R1 设计基于错误前提，已在 R2 全部改挂在商队携带概率上。

> **A5 拍板：不设稀释期**。共聚堂/藏书阁加成对老存档玩家直接生效（已造的座数立即提供 caravanProb / blueprintProb 加成）。挂机玩家上线后下次商队判定即按新概率执行——这是"上线即奖励"的正反馈，不需要数值缓冲。

### 12.2 商队来访概率加成

**方案：挂载在「共聚堂」建筑上**

理由：共聚堂主题是"狐狸聚集之地"，外来商队也更愿意造访热闹的村庄。

```js
// BD.assembly（共聚堂）新增效果
assembly: {
  // 现有：满意度 +3%/座
  // 新增：
  e: { happyP: .03, caravanProb: .02 },
  // 每座共聚堂 +2% 商队来访概率（加法叠加，上限 +10%）
}
```

引擎实现（`engine-systems.js` `trySpawnCaravan()`）：

```js
// 当前 caravanTimer >= 2 时基础概率 50%（每季判定）
const baseProb = 0.5;
const bonus = Math.min(0.10, (G.bld.assembly?.c || 0) * 0.02);
if (Math.random() < baseProb + bonus) { /* 生成商队 */ }
```

- 3 座共聚堂：50% → 56%
- 5 座上限：50% → 60%（不会破坏稀缺感）
- 不影响 ≥2 季冷却限制——商队仍不会刷屏
- **数值对照**：每座 +2% 持平商驿 +2%/座 全资源产量（[design.md:56](docs/design.md:56)）的"建筑边际加成"档。+10% 上限对照月光井 +3%/座 上限—— 5 座月光井 +15% 是 v0.14 数值标杆，本机制 +10% 设定略低（避免概率类加成超过产出类加成），保留稀缺感

### 12.3 图纸携带概率加成（修订：挂在商队上，不是远行）

**方案：藏书阁建筑加成 +「墨契」灵术一次性加成**

理由：藏书阁是知识积累的核心建筑，学识储备越深厚，商队带来的"图纸"越容易被狐狸辨认价值并被收下。"看得懂才拿得到"——自然的因果关系。

```js
// BD.library 追加效果
library: {
  // 现有：学识上限 +25/座, loreP 相关
  // 新增：
  e: { loreMx: 25, blueprintProb: .02 },
  // 每座藏书阁 +2% 商队携带图纸概率（加法叠加，上限 +10%）
}
```

引擎实现（`engine-systems.js` `trySpawnCaravan()` 商队生成成功后判定图纸携带）：

```js
// 当前基础携带概率 50%，野路子天赋 60%
const baseBpProb = G.jobTalent.merchant === 'B' ? 0.6 : 0.5;
const bpBonusBld = Math.min(0.10, (G.bld.library?.c || 0) * 0.02);
const bpBonusSpell = G.inkPactBp ? 0.15 : 0;
const finalProb = Math.min(0.95, baseBpProb + bpBonusBld + bpBonusSpell);  // 上限 95%
if (Math.random() < finalProb) {
  G.caravan.blueprint = rollBlueprint(caravanId);
}
G.inkPactBp = false;  // 用掉一次
```

- 3 座藏书阁 + 野路子未激活：50% → 56%
- 5 座藏书阁（上限 +10%）+ 野路子：60% → 70%
- 5 座藏书阁 + 野路子 + 墨契：60% → 85%（墨契用掉后立即归零）
- **数值对照**：现有商贩「野路子」永久 +10% 图纸概率（[design.md:650](docs/design.md:650)），是单档加成基准。藏书阁 5 座上限 +10% 持平野路子，让"建筑路径"和"专精路径"两种加成方式数值相当——玩家可叠加但单条线最多 +10%，避免概率突破 80% 后稀缺感崩溃

**「墨契」灵术的额外效果**：施放墨契后，下一支生成的商队携带图纸概率额外 +15%（一次性，与建筑加成加法叠加）。

```js
// 墨契施放时（castSpell）
G.inkPact = G.season;
G.inkPactBp = true;  // 额外标记

// 下一支商队生成时消耗（见上）
```

**S 档/A 档分布说明**：墨契 +15% 只提升"是否携带图纸"的概率，不影响"携带的图纸是否在 STRONG_SPECS 列表中"的判定（S/A 比例由 `STRONG_SPECS` 集合本身决定，与墨契无关）。

**墨契 +15% 数值对照**：永久档加成（野路子 +10%、藏书阁 5 座 +10%）都是低单档；墨契 +15% 是一次性脉冲——比永久档高 50%，但只对下一支商队，玩家需精确选施放时机。这种"短脉冲高数值 vs 长持续低数值"的张力是猫国"祖灵 +50% / 月光井 +3%"对照模式的同构设计。

### 12.4 汇总（修订）

| 加成维度 | 来源 | 数值 | 上限 |
|----------|------|------|------|
| 商队来访概率 | 共聚堂 ×座数 | +2%/座 | +10% |
| 商队携带图纸概率 | 藏书阁 ×座数 | +2%/座 | +10% |
| 商队携带图纸概率 | 墨契灵术 | +15%（一次性，下一支商队） | — |
| 商队携带图纸概率 | 商贩「野路子」天赋（**现有**） | 50% → 60% | — |

## 十四、前端展示策略（玩家认知负担管理）

### 14.1 设计原则

增量式揭露（Progressive Disclosure）：玩家只在需要时看到新机制，不一次性堆砌。

### 14.2 各机制的 UI 呈现

| 机制 | 展示方式 | 何时可见 |

| 节令常驻 banner | 风俗 Tab 顶部小行 `▸ 本季节令：染丝+果酒（+5% 全职业 / +8% 野莓） [展开调整]` | 持续可见（解锁后） |

### 14.3 避免"机制过于复杂"的策略

1. **零新页签**：所有新内容嵌入现有 UI 位置（灵术区/工坊区/建筑列表/日志/资源面板），不新增顶部 Tab
2. **被动+轻交互**：猎手采风/商贩路边生意/建筑维持自动结算；节令是季初一次轻交互（默认勾选沿用上季）
3. **日志即教学**：每个新机制首次触发时，日志用完整句子解释发生了什么（之后精简）
4. **tooltip 深度**：所有数值效果只在 hover 时展示详细公式，表面只显示结果
5. **渐进解锁**：
   - 玩家建了艺工坊 → 才看到纺丝帛配方
   - 玩家完成百艺通觉 → 才看到 3 个文化灵术 + 节令面板
   - 玩家建了共聚堂 → 才在 tooltip 看到商队概率加成

### 16.2 节令的"自动版"曾被考虑但弃用

第四章已说明节令为手动选择。原"自动扣除"版被否决的原因：
- 与盈库灵术抢染丝、与艺工坊维持抢染丝——多个系统隐式竞争同一资源
- 玩家体验是"东西莫名少了"而不是"我选择投入了"
- 违反路线图"持续做小决策"原则

### 16.3 双工的"×2 翻倍版"曾被考虑但弃用

第五章已说明双工为 +50% 加法。原"×2 翻倍版"被否决的原因：
- 制造"囤积爆发"退化策略——理性玩家永远不在非双工季节制作
- 与 idle 游戏稳态产出理念冲突
- 玩家会关掉自动制作攒到双工季再开

### 16.4 维持"断供归零"曾被考虑但弃用

第六章已说明维持为"半效模式"。原"断供归零"被否决的原因：
- 断崖惩罚——挂机回来发现符咒归零了几季什么都没攒到
- 不符合 idle 游戏"稳定回归"体验
- 参考猫国寒冬野莓 25%（不归零）

### 16.5 枯风口接入策略（**D1 拍板：v0.16+ 政体上线后再处理**）

**现状**：
- 文件层：[js/data.js](js/data.js) 中 EXD.windRidge 远行目的地已存在
- 命名：v0.14.1 commit `fd92e91` 将原"苍风岭"改名为"枯风口"

## 十七、自动制作（autoCraft）与新配方

> 此章节专门说明 §3 新增的 2 个配方与现有 autoCraft 系统的关系。

### 17.1 现有自动制作系统

[data.js:297-303](js/data.js:297) 中 UD.craftMastery（工法精要）的 `autoCraft: 1` 效果：玩家完成此研究后，工坊配方可在面板中切换"自动制作"。

现有可自动制作配方：木板、砖块、卷轴、染丝、果酒、墨锭。

### 17.2 新配方纳入自动制作

`weave`（纺丝帛）和 `spiceToSilk`（换丝帛）在工坊面板中与现有配方同等对待：

- 解锁 `craftMastery` 后可自动制作
- 无需新增研究节点
- 工坊面板中位列染丝/果酒/墨锭之后，作为"丝帛供应链"的本地化配方
- **A2 拍板：默认关闭自动制作**——纺丝帛/换丝帛涉及兽皮/香料等中后期稀缺资源，默认开启会让玩家不知不觉消耗大量原料；玩家需在工坊面板手动开启 auto。对照现有染丝/果酒/墨锭也是默认关闭、需玩家激活

### 17.3 玩家体验

后期玩家可设置：
- 染丝自动制作（若香料/丝帛充足）
- 纺丝帛自动制作（若兽皮/圆木充足，作为河獭商队备用方案）
- 换丝帛自动制作（若香料/铜钱充足）

避免后期手动点击疲劳，符合 idle 游戏标准。
